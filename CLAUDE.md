# CLAUDE.md

Guidance for AI agents (and humans) working in this repository.

## What this is

A TanStack Start template. The Vite project lives in **`app/`** (the npm root and Docker
context). Always run `npm`/`vite`/`vitest` commands from `app/`, not the repo root. Repo-root
files are ops only (`Makefile`, `docker-compose*`, `build-and-push.sh`).

## Stack (do not swap without asking)

- **TanStack Start** (SSR/Nitro) + **TanStack Router** (file-based) + **TanStack Query**
- **React 19**, **TypeScript 5.9** (strict), **Vite 8**
- **Tailwind CSS 3.4** + **shadcn/ui** (New York, **dark-only**) — tokens are copied, not a package
- **Vitest** + Testing Library, **ESLint 9** (flat) + **Prettier**

## Conventions

- **Path alias:** import app code via `@/…` → `app/src/…`.
- **Routes:** add files under `app/app/routes`. Authenticated pages go under `_layout/`.
  Model entities as routes (`entity.tsx` list, `entity.$id.tsx` detail, `entity.new.tsx` create) —
  prefer full routes over modals. The route tree (`app/app/routeTree.gen.ts`) is generated;
  never edit it by hand, but do keep it committed.
- **Data fetching:** one file per entity under `src/lib/queries/` exposing a **query-key
  factory** (`entityKeys`) plus `use…` hooks. Mutations must invalidate via those keys
  (`qc.invalidateQueries({ queryKey: entityKeys.lists() })`). See `src/lib/queries/example.ts`.
- **Forms:** `react-hook-form` + `zodResolver` (`@hookform/resolvers/zod`). Define the Zod
  schema alongside the entity (e.g. `exampleFormSchema` in `types/example.ts`), `register`
  fields, and show errors from `formState.errors`. Create/edit happen on dedicated routes,
  never modals. See `app/routes/_layout/example.new.tsx` and `login.tsx`.
- **API:** browser calls go through `src/lib/api-client.ts` (`api.get/post/put/delete`, builds
  the origin from `VITE_API_DOMAIN` — a bare host ⇒ `https://<host>`, or a full URL with scheme
  used as-is; the page protocol is never used); SSR/privileged calls use `createServerFn` in
  `src/lib/server-fns.ts` (uses `API_BASE_URL`). Never read `API_BASE_URL` on the client.
- **Auth:** `src/lib/auth.tsx` (`AuthProvider` / `useAuth` / `can`). 401s are handled once, in
  the root `QueryCache`/`MutationCache` (`app/app/routes/__root.tsx`) — don't scatter redirect logic.
- **Styling:** use the design-system tokens (`bg-surface-*`, `text-on-surface`, `text-k-*`,
  `.text-body-sm`, `.gradient-primary`, etc.) — see `tailwind.config.js` and `src/index.css`.
  The app is dark-only (`<html class="dark">`); do not add a light theme or `next-themes`.
- **UI components:** live in `src/components/ui`. Add new ones with `npx shadcn@latest add <x>`
  (config: `app/components.json`), then restyle to the tokens if needed.
- **Branding:** identity strings come from `src/lib/site.ts`; new projects run
  `node scripts/rename-app.mjs`.

## Verify before you finish (run in `app/`)

```bash
npm run build        # tsc -b && vite build
npm run lint
npm run typecheck
npm run format:check
npm test
```

## Gotchas

- `postinstall`/`predev` run `scripts/apply-router-plugin-patch.cjs` (an HMR patch for
  `@tanstack/router-plugin`). If HMR breaks with a "Duplicate declaration" error, re-run
  `npm install`.
- `tsc -b` needs `app/app/routeTree.gen.ts` to exist; it is regenerated by `vite dev`/`vite build`.
- **Dev server host:** `vite.config.ts` sets `server.allowedHosts: true` — the Docker dev
  container binds `0.0.0.0` and requests arrive with arbitrary host headers. Do not restrict
  this to a host list or the container will reject connections.
- **Nitro** is a runtime `dependency` (used by `npm start` → `.output/server/index.mjs`), not
  a devDependency. Do not move it.
